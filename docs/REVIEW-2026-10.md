# Code and application review — October 2026

**Goal:** a full pass over both apps for technical debt and handover. It covers every
feature, the dead code, the overcomplication, and the rules in `CLAUDE.md`.

**How it was done:** the code was read module by module, with static scans for unused
exports, props and declarations, and the duplication counts below. The key findings were
checked by reproducing them in a browser against the dev server.

**What it produced:** the architecture and data guide is now [`HANDOVER.md`](HANDOVER.md). The
same PR fixes what's listed under "Done in this PR". Everything else is the backlog below, in
priority order.

## Done in this PR

**Repo**
- Removed unreferenced screenshots (1.7 MB), the Vite `react.svg` and an unused Babel plugin.
- Removed the manual `npm run deploy`, which would have deleted the bundles CI keeps so cached
  pages don't go blank.
- Docs are rewritten: the README, this review, `HANDOVER.md`, and the Council fields doc.

**Lint**
- ESLint now understands JSX use (`react/jsx-uses-vars`). The old rule exempted every
  capitalised name, which hid dead components. Test and script `.mjs` files are linted too.

**Dead code** (about 600 lines)
- Booking site:
  - the unreachable multi-edit form and the admin schedule modal nothing opened
  - the offline "demo mode" branches: without Supabase the app shows the login screen
  - unused props, unused state and module-state setters
  - copies of the legacy-status mapping
  - ~90 needless exports
- Council fields: the retired Book mode (its code, HTML, B key and ~70 CSS selectors).

**Security**
- The `send-email` function was an open relay. Anyone signed in could create a booking under
  any address and then send it arbitrary HTML from AMUA's sender. Non-admins can now email
  only AMUA, themselves and admin-linked aliases. Addresses must be single and plain, and the
  body is size-capped.
- Booker-typed text is HTML-escaped in emails, invoices, POs and the community request.
- The PDF renderer runs with no scripts.
- CSV exports defuse formula cells.
- "Export All Data" (every booking with phone numbers) is admin-only.

**Bugs**
- Staging a shared-slot change crashed the whole app.
- A failed save during cart submit was swallowed, and the cart was then emptied.
- Moving a booking to a stage the email builder didn't know (council steps, clash,
  pending…) emailed the booker "Rejected — could not be approved".
- An admin who had looked at a booker in My fields (Council fields) had their later picks
  saved into that booker's list.
- The Council fields page showed a blank screen if the park list failed to load, and
  showed the wrong lock icon in a hint.

**Wording:** "Vendor", not "Provider", in the About tab, Summary and Council fields history.

**Database:** `supabase-setup.sql` v9 is a tidy-up with no permission or data changes.
**Re-run it, and re-deploy `send-email`.**

## Backlog

### P0 — data loss

1. **Billing records and profiles live in one browser only.** `fb_billing_records` and
   `fb_profiles` are in localStorage (`booking-system.jsx`).
   - Clearing the browser loses every official invoice, PO and receipt record.
   - Another admin's device sees none of them. Bookers always see an empty Billing tab, and
     bank-reference uniqueness is only checked locally.
   - Drive has the documents, but only after a manual sync, and nothing restores them from a
     backup.
   - **Fix:** `billing_records` and `profiles` tables (admin write, booker read-own), plus a
     one-time import from localStorage.
2. **Council fields loses edits in "local mode".** One failed 30-second refresh switches the
   page to local mode (`loadShared`). Edits saved in that window go to localStorage, and the
   next successful refresh discards them.
   - **Fix:** keep the last good mode on a transient error and retry; never replace
     `reviews` with local data while shared.
3. **Stale writes overwrite other admins' changes.**
   - "Reload data" (`handleSyncDB`) writes the old local copies of eight shared settings back
     after reloading.
   - `persistSetting` replaces whole settings values (rule 4) for `council_outcomes`,
     `facility_rates`, `pricing_conditions`, `email_aliases`, `alias_names`…
   - Admin edits to a booker's My fields merge a list loaded when the page opened.
   - **Fix:** move every booking-site settings write to `settings_merge` with per-entry
     patches, and drop the write-back from "Reload data".
4. **The activity log keeps one month by default** and is purged on every admin load. Raise
   the default (12 months?) or purge only from the retention dialog.

### P1 — security and privacy

1. **Sign-in accepts any Google account,** and `bookings` / `settings` are readable by every
   signed-in user. That includes names, emails and phones, operator relationship notes, and
   every booker's saved fields. Options:
   - an allowlist of known bookers checked by RLS (`booker_contacts` or a `members` table)
   - or narrower SELECT policies that hide other bookers' contact fields (a view without
     `phone` / `notes`).
2. **`bookings` insert lets a user set any `email`.** RLS only checks `user_id`. Consider
   checking `email` against the user's own address and admin-set aliases.
3. **Two Google OAuth client ids:** done. `councilMail.js` (the Gmail council sync) was removed;
   the council extension reads the council portal instead.
4. **The booking site never uses `shortName` (rule 2).**
   - Booker-typed names are stored and shown as typed; the form's placeholder says
     "Full name".
   - Email local parts are shown as names in about 30 places.
   - **Exceptions to document or keep:** the council contact (`booker_contacts.full_name`)
     and the billing name on official invoices.

### P2 — correctness

- **Itemised vs Grouped views filter differently.** The Itemised view ignores the venue and
  hidden facilities; Grouped ignores the status, purpose and date filters (REVIEW.md
  "sibling views").
- **Editing a booking resets its `created_at`,** which parent/child ordering uses
  (`expandRows`).
- **A booker can edit an approved or vendor-confirmed booking and it stays approved.** No
  re-review.
- **Booker-entered player counts and durations fail RLS** (settings are admin-write) and live
  only in that browser.
- **`system_notes` writes are fire-and-forget** after status writes. If one fails, the
  CLASH-PREV marker is lost and a cleared clash falls back to `pending_amua`.
- **Linked addresses:**
  - `isOwn` / `canDelete` compare raw emails, so a booker using a linked secondary address
    can't edit their own bookings.
  - The booker-filter pruning effect can un-highlight a pill whose bookings are all under
    secondary addresses.
- **Two rate defaults:** `bookingCost` uses $0 when a rate is missing, while the Summary
  uses the facility's default.
- **Bulk edit offers only half-hour starts;** bookings use quarter hours.
- **No React error boundary:** any render error blanks the page.
- **Council fields:**
  - `placeLights` uses the current field size, not each field's own.
  - The map labels a reviewer's per-profile rejection as "Rejected" for everyone.
  - `renderProfile` adds a document click listener each time it runs.

### P3 — structure (make it easier to change)

Suggested order — each step is independently shippable:

1. **Extract pure logic into plain `.js` modules with tests.**
   - Money: GST, the day/evening split, invoice and PO lines (now inside `SummaryTab` and
     duplicated ~6×).
   - The `system_notes` marker parsers and the GTEC matcher (`gtec.jsx`).
   - `parseCouncilEmail` (drives status changes; untested).
   - The Council fields geometry: `clipXY`, `councilGroups`, `splitMulti`…
   - Today only the small shared modules are testable.
2. **Shared helpers for repeated code:**
   - `downloadCsv` (5 copies), `facById` (`FACILITIES.find` ×100)
   - a display-name / canonical-email helper (8 copies)
   - `timeOverlaps` (the overlap test is inlined ×9)
   - one drag-select grid (3 implementations)
   - one `loadGis` (2 copies); `Modal` instead of hand-built overlays (4)
3. **Split `App` into hooks per concern:** `useBookings`, `useSettings`, `useCart`,
   `useGtecSync`, `useBilling`. Pass them to tabs as a few objects instead of 40-prop lists.
   Do the same for `AdminPanel` and `SummaryTab` sections.
4. **Theme tokens (rule 8):** replace the slate hexes in UI styles (`#e2e8f0`, `#94a3b8`,
   `#0f172a`, `#64748b` cover most) with `T.*` / `var(--c-…)`. That unlocks dark mode for the
   booking site.
5. **Side effects out of render:** `setModuleState` calls during render, `emailColor` caching
   during render, `showToast` and `handleMarkInvoiced` inside state updaters,
   `window.innerWidth` read during render instead of `useMobile`.
6. **Statuses (rule 7):**
   - Replace the remaining hand-written lists (`admin.jsx` council stages, `noEmailStatuses`,
     `cpsa_*` pairs) with `statuses.js` groups.
   - Name the vendor on every vendor stage (bulk actions still say "Queue for GTEC" for CPSA
     rooms).
7. **CI:**
   - `ci.yml` and `deploy.yml` repeat the same steps (a reusable workflow would do).
   - `keep_files` makes the gh-pages branch grow forever; prune bundles older than a few
     deploys.
